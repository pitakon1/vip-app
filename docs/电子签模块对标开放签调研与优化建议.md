## 0. 摘要（核心结论）

1. **开放签是「Java 单体 + Vue3」**，不是官网营销页所称的微服务；签章本质是 **PDFBox 可见签名域 + BouncyCastle CMS(PKCS#7 detached) 数字签名**，印章图片只是签名域外观。†
2. 开放签**对外 API 只接收 PDF**（≤30MB），Word/图片只能作为附件；doc→pdf 依赖**独立的外部转换服务**（`office-convert.*`）。†
3. 开放签的 **RFC3161 时间戳代码存在但默认被注释未启用**；可信时间戳实际由其商业化的「云盾」提供。†
4. 开放签许可为 **AGPL-3.0**：可参考设计与接口语义，**不能把代码复制进闭源商业产品**，否则触发网络服务开源义务。†
5. 我方已具备「免登录签署页 + 拖拽/关键字落区 + 手写签名 + 印章资产 + PDF 定位盖章 + 验签报告 + 三端入口」，功能面**接近开放签的 70%~80%**，但**工程可信度与流程严谨度差距明显**。
6. **实跑发现 1 个高危缺陷**：多人依次签署时，后一次签署会**重写整份 PDF**，导致**前一位签署人的数字签名校验结果为 `valid=0`**（§5 R1，已用现网签名产物复现）。
7. 其余高优先级缺口：上传型 Word/图片**无法转换与锚定**、**员工可代签任意签署方**、**PDF 盖章失败被静默吞掉但合同仍标记已签**、**签署方拿不到已签文件**、**无签署顺序/有效期/撤回/回调**。
8. 最高性价比的落地顺序：**修签名失效 → 上传件转 PDF → 已完成件下载+存证报告 → 失败可见化 → 签署顺序/有效期**（§6）。

> † = 开放签侧结论，来源见 §8。

- `doc.addSignature(...)` + `saveIncremental(...)`（**增量保存，保留既有签名**）；
- 证书取 PKCS#12 / JKS，`checkValidity()` + 用途校验；
- **`tsaUrl` 与 `TSAClient.java` 存在，但加时间戳的代码块被注释**。

### 2.4 后端签章流程

- **模块地图**：`modules/opensign/{controller,service,pdfbox,seal,enums,entity,mapper,aop,listener,interceptor,dto}`；
- **文件**：`SignFileController`（`/sign/file`）、`SignDocController`、`SignTemplateController`；

- **状态机 9 态**：`DRAFT / DELETED / WRITING / REFUSAL_WRITE / SIGNING / REFUSAL_SIGN / EXPIRED / RECALLED / COMPLETE`；
- **回调 13 事件**：`SEND_SIGNING / SUBMIT_WRITE / REFUSAL_WRITE / SUBMIT_SIGN / REFUSAL_SIGN / SUBMIT_APPROVE / REFUSAL_APPROVE / RECALLED / DELETE / COMPLETE / EXPIRED / SIGN_FAILED / DOCUMENT_DELAY`；POST JSON，成功须返回字符串 `"success"`，失败**立即重试 3 次**，再按 **30m / 2h / 24h** 退避。

### 2.5 前后端接口协议

| 维度 | 开放签做法 |
|---|---|
| 前缀 | 对外统一 `/resrun-paas/kaifangqian/openAPI/V2`；对内 `/sign/*` |

### 3.1 数据模型与状态机

合同状态枚举：`draft / sent / partially_signed / signed / completed / voided / rejected`（7 态）。
**实跑核对**：`completed` 在整个后端**只被读取、从未被写入**（仅 `_require_editable` 与 PDF 可见性判断引用），属死状态。开放签对应能力（完成、过期、撤回）在我方分别缺失「过期」「撤回」，而「完成」与「已签」语义重复。

**关键协议语义**：

- 免登录：`secrets.token_urlsafe(32)`，**默认 7 天、最长 60 天**，签署后 `sign_token=None` 立即失效（`contracts.py:411`）；
- `sign-batch`：`{party_id, items:[{page,x,y,w,h,method|field_type,signature_svg?,image_data_url?}]}`，**单次上限 20 个落区**，一次性原子提交（`contracts.py:1421/1441`）；
- 签前意愿：可选短信/邮箱验证码（默认不启用），公开端强制**实名（姓名 + 证件号 + 验证码）** 后才允许签署（`403 REAL_NAME_REQUIRED`）；
- 拒签：公开端 `POST /{token}/decline`；站内 `POST /{id}/decline`；仅当无剩余未签方时合同转 `rejected`；
- 作废：`POST /{id}/void` 仅允许在未签/部分签署时，转 `voided`。

### 3.3 PDF 签章实现链路

`backend/app/services/kaifang_sign_service.py`（`KaifangSignEngine`）：

1. 生成类合同：`reportlab` 渲染 HTML→PDF，落 `contracts/`，写 `pdf_path`；
2. 每次签署：PyMuPDF 打开基线 PDF（优先 `signed_pdf_path`，否则 `pdf_path`）→ `insert_image` 按百分比坐标绘入签章 PNG → **`doc.save(tmp, garbage=0)` 全量重写** → `IncrementalPdfFileWriter` 包一层 → pyhanko `PdfSigner` 用本地 PFX（`./sign-engine`，口令默认 `kfq-engine`）做一次增量签名 → 覆盖写回**同一个** `contract_{id前12位}.signed.pdf`；
3. 上传类合同：`pdf_path`/`signed_pdf_path` 均为空 → `_apply_pdf_signature` **直接 return**，只落库留痕，不产出任何已签文件（`contracts.py:1013-1020`）；
4. 任何引擎异常被 `except Exception: pass` 吞掉（`contracts.py:1035-1036`），合同状态照常推进。

验签：`GET /{id}/verify` 返回 JSON——`content_sha256`（复算 `content_html`）、`sign_digest`（HMAC）、`tampered`、逐条 `signatures[].signature_success`、`pdf_signature`（引擎逐签名 `valid/trusted/signed_by`），最终 `verified = not tampered and bool(sig_list)`。**无 PDF 版验签报告、无第三方存证机构、无时间戳。**

### 3.4 前端签署页（`frontend-web/src/pages/Sign/`）

- 路由：`publicRoutes.tsx` → `/sign/:token`，**无鉴权**，`token` 即全部凭证；
- 文档区 `DocumentPanel.tsx`：PDF 走 `pdf-pages/{page}` 的**整页 PNG**（`<img>`）+ 翻页；非 PDF 上传件走 `<iframe src=file>`；**无缩放、无旋转、无缩略图导航**；
- 落区 `usePlacement.ts` + `SignFieldBox.tsx` + `PlacedBox.tsx`：预置虚线框点击落章；托盘（签名/印章/日期）拖入文档，坐标转百分比；支持撤销；
- 手写 `SignCanvas.tsx`：`pointer` 事件 + `canvas` 绘制，导出**纯 SVG path 字符串**，再光栅化为 PNG 供 PDF 盖章；
- 印章 `SealModal.tsx`：模板生成（调后端 `generate-seal`）/ 印模上传（本地裁剪）/ 复用；`CompanySeal.tsx` 为本地 SVG 预览；
- 身份 `RealNameModal.tsx`：姓名 + 证件号 + 短信/邮箱验证码；
- 拒签 `DeclineModal.tsx` + `DeclinedView`；
- 结果 `StatusViews.tsx` 的 `SuccessView`：**只有成功文案与「返回」类操作，没有「下载已签 PDF」「下载验签/存证报告」按钮**；
- 多人：`SignerAside.tsx` 展示各签署方已签/未签状态，**无顺序约束、无「轮到谁」概念**。

## 5. 已确认短板与风险（按严重度）

| ID | 风险 | 影响 | 证据 |
|---|---|---|---|
| **R1** | **多人签署导致前序数字签名失效** | 已签合同在 Adobe/第三方验签时显示「签名无效」，司法举证风险最高 | 实测 V5：合同 A `[{valid:0},{valid:1}]`；根因 `kaifang_sign_service.py:404` 先 `doc.save()` 全量重写，破坏已有 ByteRange |

## 6. 优化建议（按性价比排序）

成本口径：**S** = 单点改动、无新依赖；**M** = 跨 2~4 个模块；**L** = 需新增服务/依赖或改数据模型。

### 6.1 A 类：可立即落地（无新依赖，S/M）

| # | 事项 | 做法要点 | 收益 | 成本 | 验收 |
|---|---|---|---|---|---|
| A1 | **修复多签署人签名失效（R1）** | `sign_pdf` 改为直接从基线字节构建 `IncrementalPdfFileWriter`，**去掉 `doc.save()` 全量重写**；贴图改用 pyhanko 签名外观（或先贴图再一次性签名，全程增量） | 消除最高危举证风险；验签全绿 | M | 两方签署后 `verify_pdf` 两条均 `valid=1`；Adobe 打开无「签名无效」 |
| A2 | **已签文件与存证报告可下载（R8/§4-22）** | 新增 `GET /public/contract-sign/{token}/signed-pdf`（token 签署后保留「只读下载」短窗口或改用独立 download_token）；`GET /contracts/{id}/verify-report.pdf` 由后端生成 PDF | 客户可自取已签件；支撑交付闭环 | M | 签署成功后结果页出现两个下载按钮，实测可下载 |
| A3 | **上传件统一转 PDF（R2）** | 上传后立即尝试转换：PDF 直接写 `pdf_path`；图片用 PyMuPDF 包一层 PDF；doc/docx 走可选转换（见 B1） | 恢复预览/页图/锚定/已签件 | M | 上传 pdf/png 后 `pdf_page_count > 0`、`pdf-pages/1` 返回 200 |
| A4 | **签章失败可见化（R4）** | 去掉裸 `except: pass`；失败写 `contract.last_sign_error`，`sign-batch` 返回 `pdf_signed: false`，前端提示「文档签章失败，请联系管理员」 | 避免「假已签」 | S | 注入异常后接口返回明确字段、状态不静默推进 |
| A5 | **上传件哈希取文件字节（R3）** | 完成时对 `file_path`/`pdf_path` 字节做 sha256；`content_hash` 仅用于生成类 | 哈希与真实文件强关联 | S | 验签报告 `document_hash` 与文件 `sha256sum` 一致 |

| A8 | **清理死代码（R12）** | 删除或补齐 `pdfFileUrl` | 减少误用 | S | `tsc` 通过、无引用 |

### 6.3 C 类：需产品决策（不建议现在写代码）

| # | 决策点 | 选项 | 说明 |
|---|---|---|---|
| C1 | **是否引入 CA/云盾类服务** | 自签 CA（现状）/ 第三方 CA（开源 TSA + 商业 CA）/ 接入开放签云盾 | 直接决定 R9 的处理方式与成本；自签永远只有平台内可信 |
| C2 | **上传件格式白名单** | 放开 doc/docx（需 B1）/ 仅 PDF+图片 | 前者体验好但引入转换依赖与失败面；后者最稳，与开放签口径一致 |
| C3 | **员工代签边界（R5）** | 允许（需留授权+审计）/ 仅允许「本人绑定」/ 禁止 | 涉及业务实际作业方式，不能由技术单方面收紧 |
| C4 | **是否需要对外 OpenAPI** | 不需要（仅站内）/ 需要（对齐开放签 appAuthToken + RSA 签名） | 若仅站内，§4-19 的差距可接受 |
| C5 | **存证深度** | 仅内部哈希 + 报告 / 哈希上链 / 第三方存证机构 | 影响 R8/A2 的报告模板与法律口径 |
| C6 | **有效期与拒签后重签** | 拒签终态（现状）/ 允许复制新合同 | 开放签为不可恢复，建议保持一致 |

### 6.4 建议实施顺序

```
P0（先做，止血）：A1 → A4 → A5 → A6
P1（体验闭环）：A2 → A3 → A7 → A8 → B2
P2（能力补齐）：B3 → B4 → B1（若 C2 选择放开 Word）
P3（合规升级）：B6 → B5（依赖 C1）
```

**理由**：A1/A4/A5 都是「让已签合同在事后经得起验证」的底层问题，改动小、收益最大；A2/A6 直接补齐产品已明确要求的「签署完成文件下载 + 存证报告」；B2/B3 是状态机正确性；B1 是体验问题但依赖产品决策 C2。

## 7.3 P1-2～P3 优化落地记录（2026-11-12）

范围：§6 剩余优化项**一次性全部落地**（P1-2 上传件转 PDF、P1-3 签署 token 收紧、P1-4 多人签署顺序、P2-1 有效期、P2-2 完成回调、P3-1 企业印章库、P3-2 可信时间戳）。仅使用开源组件，未引入 AGPL，未提交 git。

### 7.3.1 后端实现与接口

| 项 | 实现 | 关键接口 / 文件 |
|---|---|---|
| P1-2 上传件转 PDF | PDF 原样使用；图片（jpg/png/webp/gif）用 reportlab 按 A4 等比包页；doc/docx/xls/xlsx 调用 Gotenberg（LibreOffice）。转换失败**不阻断上传**，响应 `pdf_converted=false` + `pdf_convert_error`，可重试 | `app/services/pdf_convert.py`；`POST /contracts/{id}/upload`、`POST /contracts/{id}/convert-pdf` |
| P1-3 token 收紧 | 免登录 token 默认有效期 7 天 → **3 天**，显式指定封顶 7 天（原 60）；**兼容在途链接**：token 格式与校验逻辑未变、无数据迁移，已发出的未过期链接继续有效；复制链接/二维码/重发通知默认 `reuse=true` 复用未过期令牌，只有显式不带 `reuse` 调用才轮换（旧 token 404）；已签 409 | `contracts.py::_DEFAULT_TOKEN_DAYS` / `_MAX_TOKEN_DAYS` / `_issue_sign_token`、`POST /contracts/{id}/share-link` |
| P1-4 顺序编排 | 新增 `sign_order_type`（parallel/sequential）与 `ContractParty.sign_order`；串行时后序提交返回 409 `NOT_YOUR_TURN` 且零留痕；已签方不可改序号、同序号（同轮）拒绝 | `POST /contracts/{id}/sign-order`；`_can_sign_now` / `_ensure_sign_turn` |
| P2-1 有效期 | `Contract.expires_at`；发送时按 `sign_expires_in_days`（默认 30，clamp 1–90）设置，已过期则续期并把 `expired` 拉回可签态；过期后公开页 410、登录态签署 409，状态置 `expired`，不产生签署留痕 | `_ensure_not_expired`、`POST /contracts/{id}/send` |
| P2-2 完成回调 | `Contract.callback_url/secret` + `ContractCallbackEvent`；全部签完触发 `contract.signed`，`HMAC-SHA256` 签名头 `X-Contract-Signature`、`X-Idempotency-Key=合同id:事件`；失败仅记录不影响签署；支持人工重投且已送达不重复发送（投递模型已由 §7.3.5 升级） | `POST /contracts/{id}/callback`、`GET /contracts/{id}/callbacks`、`POST /contracts/{id}/callback/retry` |
| P3-1 企业印章库 | `SignAsset.scope`（personal/company）；company 仅员工可读写、仅允许 `asset_type=seal`、全员工可见、删除限创建人或 admin（印章类别已由 §7.3.5 补充） | `GET /sign-assets?scope=company`、`POST /sign-assets`、`POST /sign-assets/imprint` |
| P3-2 可信时间戳 | 仅当配置 `TSA_URL` 时给 pyhanko 注入 `HTTPTimeStamper`（RFC 3161），失败只记日志不阻断签名；默认关闭 | `app/services/kaifang_sign_service.py::_make_timestamper`、`app/config.py::TSA_URL` |

| 项 | 实现 | 关键接口 / 文件 |
